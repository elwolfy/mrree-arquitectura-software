## 1. Contexto y Objetivo

En el consulado, un ciudadano que ya cuenta con una cita `RESERVADA` puede necesitar cambiarla de fecha u hora (**reprogramación**). Sin embargo, el Ministerio establece dos políticas estrictas:

1. **Integridad de cupos (CAP):** Al reprogramar, el sistema debe liberar el cupo anterior y ocupar el nuevo cupo sin permitir jamás que una franja horaria supere su capacidad máxima, incluso si múltiples ciudadanos intentan tomar el último cupo al mismo tiempo.
2. **Plazo mínimo de anticipación (Regla de dominio):** Solo se permite reprogramar una cita si faltan **al menos 24 horas** ($\ge 24\text{ h}$) para la fecha y hora actuales de la cita. Si faltan menos de 24 horas, el sistema debe rechazar la solicitud con HTTP `422 Unprocessable Entity` (`reprogramacion-fuera-de-plazo`) porque ese cupo ya no podría ser reasignado a tiempo a otro ciudadano.

El equipo de arquitectura ya dejó construido todo el andamiaje en `m1-estilos/monolito-modular`: el endpoint REST `PUT /api/citas/{citaId}/reprogramacion`, el caso de uso transaccional `ReprogramarCitaService`, el bloqueo pesimista de cupos y el manejador global de errores RFC 9457. Actualmente, el endpoint devuelve `501 Not Implemented` porque la regla de dominio en `ReglaDeReprogramacion` está pendiente.

**Su objetivo** es documentar la decisión de consistencia (CP vs. AP) de la reprogramación y completar la regla de dominio de las 24 horas respetando la arquitectura hexagonal verificada por ArchUnit.

### Tarea 2 — Regla de Dominio de las 24 Horas y Pruebas (25 minutos)

1. Abra `ReglaDeReprogramacion.java` en el paquete `pe.utec.consular.monolito.citas.domain`.
2. Reemplace el `throw new UnsupportedOperationException("Asignación A1 pendiente");` del método `validar(Cita cita, LocalDateTime ahora)` por la lógica de negocio:
   - Calcule el tiempo restante entre `ahora` y la fecha/hora programada en la cita actual (`LocalDateTime.of(cita.getFecha(), cita.getHora())`) utilizando la API estándar `java.time.Duration`.
   - Si faltan **menos de 24 horas**, lance `ReprogramacionFueraDePlazoException` con un mensaje descriptivo en español.
   - Si faltan **24 horas o más**, el método termina normalmente sin lanzar excepción.
   - **Importante (Gobernanza Hexagonal):** No importe ninguna clase de Spring (`org.springframework.*`), JPA ni adaptadores en `ReglaDeReprogramacion.java`; la regla `dominio_no_depende_de_infraestructura` de `ReglasDeArquitecturaTest` verificará que el dominio se mantenga puro.
3. Abra `ReglaDeReprogramacionTest.java` y elimine la anotación `@Disabled("Asignación A1")` (y su `import` si queda sin uso).

### 4.3 Verificar el endpoint REST con Swagger UI o `curl` / PowerShell

Puede usar Swagger UI en `http://localhost:8081/swagger-ui.html` (`PUT /api/citas/{citaId}/reprogramacion`) o ejecutar en PowerShell:

1. **Crear una cita en un día hábil a más de 24 horas y reprogramarla a otro día hábil (`200 OK` con `estado: REPROGRAMADA`):**
   ```powershell
   # Función auxiliar para elegir el N-ésimo día hábil (lunes a viernes) a partir de hoy
   function Obtener-DiaHabil([int]$diasHabiles) {
       $d = (Get-Date).Date
       $c = 0
       while ($c -lt $diasHabiles) {
           $d = $d.AddDays(1)
           if ($d.DayOfWeek -ne 'Saturday' -and $d.DayOfWeek -ne 'Sunday') { $c++ }
       }
       return $d.ToString("yyyy-MM-dd")
   }
   $fInicial = Obtener-DiaHabil 4
   $fNueva   = Obtener-DiaHabil 5

   # 1. Reservar cita inicial
   $cita = Invoke-RestMethod -Uri "http://localhost:8081/api/citas" -Method Post -ContentType "application/json" -Body (@{
       dni = "40000010"; nombres = "Carlos Mendoza"; email = "carlos@correo.lab";
       oficinaId = "MAD"; fecha = $fInicial; hora = "09:00"; tipoTramite = "LEGALIZACION"
   } | ConvertTo-Json)

   # 2. Reprogramar cita (faltan > 24 h -> debe responder 200 OK y estado REPROGRAMADA)
   Invoke-RestMethod -Uri "http://localhost:8081/api/citas/$($cita.id)/reprogramacion" -Method Put -ContentType "application/json" -Body (@{
       fecha = $fNueva; hora = "10:30"
   } | ConvertTo-Json)
   ```

2. **Intentar reprogramar una cita cuando faltan menos de 24 horas (`422 Unprocessable Entity` con `type: https://consular.lab/errores/reprogramacion-fuera-de-plazo`):**
   - Si reserva una cita para mañana a las `08:00` (o actualiza una cita de prueba en la base de datos para que su fecha/hora esté a menos de 24 horas de la hora actual en `America/Lima`) e invoca `PUT /api/citas/{id}/reprogramacion`, debe recibir HTTP `422` con `codigo: "reprogramacion-fuera-de-plazo"`.
